# 待办设计

支持在当前固定的或 env 中指定的 port 基础上，在被占用时向后查询可用端口，支持设置最大查询范围，超过范围则报错。
支持指定redis的host和port，支持redis密码验证，支持redis key前缀设置。
将核心部分封装为一个独立的可执行文件，这个文件会优先读取同目录下的 .env 文件，若不存在则读取 env 中的环境变量。
支持通过command自定义插件目录，在开发环境默认使用 `projects/server/plugins`，在生产环境默认使用同目录下的 `plugins`，并支持通过 env 中的 `SCWC_PLUGIN_DIR` 指定插件目录，当在 env 中指定了 `SCWC_PLUGIN_DIR` 时，再通过 command 指定时会先警告“环境中的 SCWC_PLUGIN_DIR 将会被覆盖”，用户确认后才会覆盖。

补充控制台输出功能，支持多输出窗口，当前为 tui，修改为占满整个终端的输出窗口。
支持持久化，将在退出时保存当前所有窗口的状态，并在下次启动时恢复。关闭时被强制中断的命令不会继续执行，而是会保存中断后的输出，并在启动后一起显示。
在顶部显示所有当前输出窗口的标题，默认开启两个窗口，第一个窗口显示程序输出“输出窗口”，无法关闭，第二个窗口为命令和命令输出窗口“命令窗口”。

顶部为标签栏，第一个标签固定为“输出”，其余标签为“cmd+数字”，数字为窗口的编号，默认使用当前最小的未使用编号，当某个窗口执行命令时，标签栏会显示该窗口的标题，标题为当前执行的命令的主命令(例如“plugin ps” 则会显示为“plugin”)，尾部窗口编号左侧显示一个通过多个加载的字符替换的加载动画（⠋⠙⠹⠸⠼⠴⠦⠧⠇⠏），当命令执行完成后，标题会恢复为原来的标题。标签项的尾部显示一个数字，可以通过命令切换窗口，数字为从左到右依次的顺序，从 0 开始（“输出窗口”），之后的全局命令可以通过指定窗口编号来执行命令。当标题过长时，聚焦的标题会滚动显示，其他标题会被截断显示省略号，鼠标悬停在标题上时页会滚动显示对应的过长的标题内容。当窗口数量过多时，会在超出界面方向的一侧或两侧显示箭头，鼠标点击箭头可以滚动一个单位的窗口标题，也可以用鼠标滚轮以终端字符单位滚动，也可以通过左右键滚动一个单位的窗口标题。但是当切换标签页时，需要调整到这个标签页在可视范围内。可以通过 tab 和 shift+tab 切换窗口。可以通过鼠标点击切换窗口。可以通过全局命令切换窗口，这部分在下面的全局命令中有详细说明。

中间为输出显示部分，显示当前窗口的输出内容，支持滚动查看历史输出内容。支持通过鼠标滚轮或上下方向键滚动查看当前窗口的输出内容。支持通过 cmd+up 和 cmd+down 切换命令历史记录（命令窗口中），每个窗口独立维护自己的滚动位置和历史记录，切换窗口时不会改变当前窗口的滚动位置和历史记录。

底部为类似 vim 的底部命令行模式，支持在任何窗口中输入 ":" 切换到底部命令行模式，在这里实现全局命令。二次确认消息在底部命令行的上方显示，这将会挤占中间为输出显示部分的一行或多行。二次确认消息显示时，只允许执行消息中指定的命令输入，此时可以将任意其他键盘输入映射为其中一个指定的命令输入，其他全局命令输入将会被忽略，直到用户执行了指定的命令输入后，二次确认消息消失，底部命令行模式恢复正常。

底部全局命令：
:q 退出整个程序，如果有任何任务或插件正在执行中，则会提示“当前有任务正在执行，是否确认退出？”，用户确认后才会退出整个程序，使用 :y 确认，:n 或任意其他键放弃。（这需要添加一个接口，用于设置当前进程是否有任务在执行，核心为一个进程，插件各为一个进程，这个接口将会被开放给插件，通过 onload 注入）
:w 关闭当前窗口，如果当前窗口有命令正在执行中，则会提示“当前窗口有命令正在执行，是否确认关闭？”，用户确认后才会关闭当前窗口，使用 :y 确认，:n 或任意其他键放弃。
:r/:restart 重启整个程序，如果有任何任务或插件正在执行中，则会提示“当前有任务正在执行，是否确认重启？”，用户确认后才会重启整个程序，使用 :y 确认，:n 或任意其他键放弃。
:s/:switch 切换到指定编号的窗口，使用 :s 0 切换到第一个窗口，:s 1 切换到第二个窗口，以此类推。
:c/:close 关闭指定编号的窗口，使用 :c 0 关闭第一个窗口，:c 1 关闭第二个窗口，以此类推。如果当前窗口有命令正在执行中，则会提示“当前窗口有命令正在执行，是否确认关闭？”，用户确认后才会关闭指定编号的窗口，使用 :y 确认，:n 或任意其他键放弃。

部分快捷键需要阻止冒泡，防止触发所用终端的快捷键。在windows和linux中需要把cmd键替换为ctrl键。

当前的终端为通过projects/server/scripts/setup.ts启动核心服务，setup.ts 拦截了 restart 输入，并在 restart 时重新执行核心服务；并作为代理，将核心程序的输出转发到终端，将其他输入转发到核心程序。这意味当前的命令执行和输出实际上是由核心程序执行的，setup.ts 只是作为一个代理。
要想实现上面的功能，同时仍然支持 restart, 需要开发一个完整的多标签终端功能。

修改后需要把终端作为一个独立的工程，放在 projects/terminal 中，projects/server/scripts/setup.ts 只负责将服务启动到终端，终端将直接和核心服务进行通讯。
核心服务当前的命令行交互功能保留，仅在直接启动核心服务时启用。通过上面的终端启动时则执行和终端的通讯执行模式。

为了后续开发，终端需要支持插件化，插件可以通过注册命令的方式扩展终端的功能。插件目录为 `projects/terminal/plugins`，可以通过 env 中的 `SCWC_CMD_PLUGIN_DIR` 指定插件目录。
