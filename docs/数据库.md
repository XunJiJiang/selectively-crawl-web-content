# SCWC 核心数据库

> 核对日期：2026-10-18。本文是已实施的核心数据库 schema、路径与恢复说明。
> 不包含 `projects/server/plugins/` 内各插件自有的数据库、表和迁移。

## 1. 当前状态

核心已新增两个独立 SQLite 数据库，使用已有 better-sqlite3：工作台库保存工作区、收藏、关闭历史、Web 终端及通知；插件配置库只保存按插件目录隔离的字符串 KV 和定义元数据。采集接口仍只分发给插件，不自动保存采集结果。

| 数据库 | 默认位置 | 所有权 |
| --- | --- | --- |
| 工作台 | `ENV_DIR/data/web/workbench.sqlite` | 核心 Web 工作台 |
| 插件配置 | **`ENV_DIR/data/scwc/plugin-config.sqlite`** | 核心管理，每插件目录独立命名空间 |
| Redis | 配置的 Redis 服务 | 可选缓存，不保存上述数据库的业务事实 |

`SCWC_DATA_DIR` 指定运行时 data 目录，相对路径以 ENV_DIR 解析；插件配置库固定在该目录的 `scwc/plugin-config.sqlite`。工作台默认在同一 data 目录的 `web/`，可单独用 `SCWC_WEB_WORKBENCH_DB` 覆盖。源码运行 ENV_DIR 是仓库根，发行版为部署目录；不使用 cwd 或 SERVER_ROOT 临时释放目录。

核心启动自动创建目录、建表并迁移至 `PRAGMA user_version=1`。无需手工建库命令。不支持打开更高版本；WAL、foreign_keys=ON、busy_timeout=3000。两个库分别提交，不承诺跨库事务。

## 2. 已实现的 Redis 缓存

### 2.1 配置与初始化

配置由 `common/config.ts` 的 `redisSettings()` 解析，`utils/cache.ts` 在启用时创建 Keyv Redis 适配器。核心不会代为安装或启动 Redis 服务。

| 环境变量 | 默认值 | 含义 |
| --- | --- | --- |
| `REDIS_ENABLED` | `true` | 接受 `true/1/false/0`；关闭后不创建 Redis 客户端 |
| `REDIS_HOST` | `127.0.0.1` | Redis 主机，支持 IP 或合法主机名 |
| `REDIS_PORT` | `6379` | 端口，1–65535 |
| `REDIS_USER` | 未设置 | 非空时传入用户名 |
| `REDIS_PASSWORD` | 未设置 | 非空时传入密码 |
| `REDIS_TIMEOUT` | `5000` | 连接超时，单位毫秒，正整数 |
| `REDIS_KEY_PREFIX` | `cache-redis` | 当前核心实例的缓存命名空间 |

`.env` 中已提供的键优先于进程环境；完整模板见 [core.env.example](./core.env.example)。不需要 Redis 的最小配置：

```dotenv
REDIS_ENABLED=false
```

关闭 Redis 后仍有内存和文件缓存，但没有 Redis 元数据跨核心进程复用能力。

### 2.2 键与逻辑值

核心注入的插件缓存命名空间为 `plugin:<插件目录名>`。默认 Redis 键示意：

```text
cache-redis::plugin:<插件目录名>:<调用者的key>
└ 实例前缀   └ 插件命名空间      └ 业务缓存键
```

前缀不能是空串，也不能包含空白及 Redis 匹配通配符等被配置解析器禁止的字符，因为清理需要按前缀匹配。多个核心实例共用 Redis 时应分别配置前缀。

下表是 `utils/cache.ts` 提交给缓存层的**逻辑记录**，不是承诺可直接操作的 Redis 原始序列化格式；实际编码由 Keyv/适配器负责。

| `type` | `dataType` | `data` | 用途 |
| --- | --- | --- | --- |
| `value` | 原始类型标识或 `Buffer` | 缓存值 | 小值缓存 |
| `redirect` | `string` | 已含命名空间的最终目标键 | 键重定向 |
| `filecache:<类型>` | `string` | 溢出文件路径 | 超过 5 MiB 的值或核心流缓存 |

这里没有业务表、关系约束或 schema migration。调用方通过核心缓存控制器读写，不能把这些记录当作稳定业务数据库模型。

### 2.3 生命周期与恢复边界

- 上层缓存默认 TTL 为一小时；内存还有 LRU 容量限制。缓存可能自然过期或被删除，不提供业务持久性保证。
- 核心正常退出会清空本实例缓存及文件缓存目录；核心重启跳过主动清理，但内存仍随进程结束而消失。
- 仅备份 Redis 不能恢复溢出文件；仅备份 `cache/files` 也不能恢复键及类型映射。溢出记录中的路径还与部署位置相关。
- 删除或过期缓存键不会立即删除对应文件，文件在整体清理时删除。
- Redis 的 RDB/AOF、服务级备份和运维策略不由当前核心配置或管理。

## 3. 非数据库存储对应关系

| 数据 | 当前保存位置 | 是否由 Redis 保存 |
| --- | --- | --- |
| 浏览器采集规则、连接 token、浮窗状态 | 各页面 origin 的 localStorage | 否 |
| 终端窗口、输出、历史、插件冲突偏好 | `ENV_DIR/data/terminal/state.json` 及备份 | 否 |
| 核心插件启用状态 | 插件 `package.json.enabled` | 否 |
| 插件通过核心缓存保存的值 | 内存、可选 Redis、溢出文件 | 可能 |
| `writeData()` 输出 | 调用者目录的 `data.json` 和 `images/` | 否 |

这些文件格式是各模块的契约，不应在本文件中虚构成数据库表。

## 4. SQLite schema v1

### 4.1 插件配置库

| 表 | 字段与约束 | 读写入口与删除策略 |
| --- | --- | --- |
| config_values | `plugin_id TEXT`、`key TEXT` 联合主键；`value TEXT NOT NULL CHECK(typeof(value)='text')`、`updated_at TEXT NOT NULL` | config.update/set 写，get/list 读；delete/reset 删除覆盖；停用/卸载/退出不清理 |
| config_revisions | `plugin_id TEXT PRIMARY KEY`、`revision INTEGER NOT NULL` | 每插件 CAS；一次批量变更一个 revision |
| config_definitions | `(plugin_id,definition_id)` 主键，schema_version、descriptor_json 为非空 TEXT，revision 为 INTEGER | 后端 configuration.definitions 或页面 grant 注册；只保存声明，不保存函数源码 |

plugin_id 是插件目录名；重命名目录视为新命名空间。key 是1–200字符的原样字符串，value≤64KiB，每插件最多2000个覆盖键；允许空字符串，拒绝 null、数字、对象、控制字符键及危险原型段。点分键不拆层，JSON 编解码由插件负责。

默认值只在 config_definitions 元数据中，读取不会插入默认覆盖。有效值=当前默认+用户覆盖；reset 删除覆盖后立即采用当前默认。没有定义/没有覆盖时 get 返回 undefined。值和 revision 在一个事务提交，再发 config.changed；自定义验证在事务外，提交前重查 revision/schemaRevision。

后端对象及 HTTP 接口见[Web 后端接入](Web后端接口.md#5-插件后端配置对象)。

### 4.2 工作台库

下表列出全部业务字段；除特别注明外，ID/JSON/时间/status 为 TEXT，revision/seq 为 INTEGER，必填字段由 DDL 的 NOT NULL 与服务校验共同约束。JSON 是各实体的序列化内容，不包含 DOM、闭包、TOKEN、grant、票据或 next 回答。

| 表 | 主键和字段 | 读取/写入与保留 |
| --- | --- | --- |
| installation | id 主键、schema_version | 首次生成稳定 installationId |
| preferences | profile_id 主键、value_json、revision | local profile 的主题、快捷键和节能偏好；CAS，重置删除覆盖字段 |
| workspaces | id 主键、profile_id、snapshot_json、revision | 完整 layout/tabs；租约和 CAS；不读取 CLI 状态 |
| bookmarks | id 主键、value_json、revision | URL、locator、标题、previewId；独立于打开标签 |
| closed_tabs | id 主键、operation_id、batch_id、profile_id、workspace_id、plugin_id、closed_at、restored_at（可空）、value_json | 插件标签实际关闭时与工作区原子写；90天/10000条 |
| snapshots | id 主键、kind、owner、plugin_id、checksum、metadata_json、payload BLOB、created_at | 状态/PNG；所属校验、sha256；引用中不可删，总量25MiB/100MiB，满额拒写 |
| terminals | id 主键、workspace_id 外键→workspaces(id)、value_json、revision | 标题、草稿、历史、archivedAt；关闭为归档 |
| executions | id 主键、terminal_id 外键→terminals(id)、boot_id、status、command、request_key UNIQUE、value_json | 执行接受收据；启动将 running/returned 标 interrupted；不重跑 |
| output_records | (stream_id,seq) 主键、timestamp、value_json | 持久有序输出；每流10000条/10MiB、总100MiB、7天；查询返回 truncatedBefore |
| output_streams | id 主键、seq 默认0 | 即使输出被清理仍不复用序号 |
| notifications | id 主键、source_key、dedupe_key（可空）、value_json、updated_at | 来源固定、去重和共享已读；30天/1000条 |
| operation_receipts | request_key 主键、fingerprint、result_json、created_at | 工作区保存/关闭/恢复及 Job 创建幂等，7天 |
| jobs | id 主键、value_json、updated_at | 阶段、状态、revision、最多500条日志；7天，重启失败关闭未完成任务 |

附加索引：closed_tabs_time(profile_id,closed_at DESC,id)、closed_tabs_plugin(plugin_id,closed_at DESC)、closed_tabs_batch(batch_id)、notifications_dedupe(source_key,dedupe_key)。分页、CAS 和多行变更在各自数据库事务中处理。租约、页面 grant、WS ticket、在线输入、事件补流环形缓冲保存在内存，重启失效。

### 4.3 备份、恢复与清理

正常退出先结束操作和日志 flush，检查 quick_check，再用 SQLite backup API 为每个库创建相邻 `.backup` 健康备份；不能直接复制仍在写入的 WAL 主文件。`WorkbenchStorage.backup(directory)` 可生成带时间戳的两库导出，它们不是跨库一致性快照。

启动发现损坏时，先验证相邻 `.backup`；健康才把主库和 WAL/SHM 改名为 `.corrupt-<timestamp>` 保留现场，再恢复备份。主库和备份都不健康时拒绝启动，不创建空库覆盖数据，也不更新最后健康备份。恢复只保证备份已提交边界，最后一次健康备份之后的变更可能需要人工恢复。建议部署运维另外保留离线/定期备份。

期限清理在启动和正常退出执行；通知和输出写入还执行容量限制。插件停止不删除配置、收藏、历史或工作台逻辑标签。快照采用显式无引用删除，尚未自动 LRU 清理。删除历史不会触碰任意用户目录。备份/导出默认不包含主 TOKEN、grant、WS ticket 和临时输入回复。
