# 核心服务配置与独立部署

## 源码启动

```sh
bun run dev:server --plugin-dir=./my-plugins --port=3200 --port-range=20
node projects/server/index.ts --mode=dev --plugin-dir=./my-plugins
```

源码模式读取仓库根 `.env`，不受启动工作目录影响。文件中提供的键优先于进程环境变量，文件未提供的键使用进程环境变量。CLI 的 port / port-range 优先于这两者。

## 配置

完整模板在 [core.env.example](core.env.example)。无效端口、查询范围或 Redis 配置会明确报错，不静默使用另一个值。

| 配置 | 默认值 | 说明 |
| --- | --- | --- |
| PORT | 3200 | HTTP 起始端口，1–65535 |
| PORT_SEARCH_RANGE | 20（自动限制到 65535） | 最大递增偏移；候选范围含起始端口与末端。显式配置不得越过 65535；0 禁止递增 |
| HOST | http://localhost | 公布服务 URL 的主机前缀，保持现有监听行为 |
| TOKEN | 随机 UUID | 字面值 null 关闭验证，留空生成随机值 |
| REDIS_HOST | 127.0.0.1 | 主机名、IPv4 或 IPv6；不含协议 |
| REDIS_PORT | 6379 | Redis 端口，1–65535 |
| REDIS_USER | 空 | 可选 ACL 用户 |
| REDIS_PASSWORD | 空 | 可独立设置密码，支持特殊字符；含 # 的值在 .env 中加引号 |
| REDIS_TIMEOUT | 5000 | 连接超时，毫秒，正整数 |
| REDIS_KEY_PREFIX | cache-redis | Redis 命名空间；不能为空或含空白、Redis 通配符 |
| SCWC_PLUGIN_DIR | 见下文 | 核心业务插件目录 |

端口只在绑定返回 EADDRINUSE 时递增，其他错误立即失败。绑定成功后的日志及 `server info` 显示实际端口；浏览器配置仍需填写这个实际端口，本次不引入自动服务发现。

Redis 使用连接选项传递密码，避免拼接 URL 时破坏密码里的特殊字符。Redis key 形如 `<前缀>::plugin:<插件目录名>:<key>`；核心清理缓存仅影响当前前缀，多个部署共享 Redis 时请使用不同前缀。旧版本可能存在双重前缀的缓存键，升级后不读取这些旧缓存，等待原 TTL 到期即可。

插件目录优先级：命令行 `--plugin-dir`（需要时确认）→ SCWC_PLUGIN_DIR → 模式默认值。开发模式默认仓库的 `projects/server/plugins`；生产模式默认程序所在目录的 `plugins`（源码入口所在目录是 `projects/server`）。环境变量中的相对路径以 `.env` 配置目录为基准，CLI 相对路径以启动工作目录为基准。

同时指定 SCWC_PLUGIN_DIR 和 --plugin-dir 时打印“环境中的 SCWC_PLUGIN_DIR 将会被覆盖”，直接运行核心时输入 y 才覆盖；通过终端启动时在底部输入 :y 加 Enter 确认，:n / Esc / 其他输入取消。确认发生在 HTTP 服务启动和插件加载之前；通过 setup.ts 启动时，同样由核心确认。没有设置环境目录时，CLI 直接生效。

## 构建独立可执行文件

```sh
bun install
bun run build:core
```

构建需要 **Node.js >= 25.5**，使用内置 `--build-sea`；源码运行仍支持 Node.js 24。当前生成运行构建的操作系统与 CPU 架构版本；macOS 自动使用临时签名。其他平台请在对应平台构建与验证，不把本机验证视为跨平台验证。

输出在 `dist/core/scwc`（Windows 为 scwc.exe），包括 Node 运行时、核心依赖、多窗口终端及两类插件宿主、Web 页面、scwcutils、公共图标/字体和错误页面模板。不把 .env、业务插件、插件数据或插件私有页面打进核心。构建不会复制当前配置的密码或 token；只提供 `.env.example`。

采用 Node SEA，以保持已有 Node 插件及高级 IPC 序列化兼容。机制参考 [Node 官方单文件应用文档](https://nodejs.org/api/single-executable-applications.html)。

核心、终端和两类宿主在构建时均经 esbuild 转换为 JavaScript、合并依赖、tree shaking 和压缩，保留函数/类名便于异常诊断。这里没有 SSR 页面水合；如果“水合”指依赖合并，bundle 已覆盖。Node 直接运行 TS 会先擦除类型，再执行 JavaScript，不会利用 TS 类型做额外运行优化；预编译主要省去加载时的类型处理，合并和压缩主要减少读取与解析体积，业务运行速度仍取决于实际 JS、I/O 和算法。参见 [Node TypeScript 文档](https://nodejs.org/api/typescript.html) 与 [esbuild 构建选项](https://esbuild.github.io/api/)。

部署示例：

```text
deployment/
├── scwc（或 scwc.exe）
├── .env（可选）
└── plugins/
    └── my-plugin/
        ├── package.json
        ├── index.ts / index.js
        └── 插件自身的依赖与资源
```

可以从其他工作目录启动该可执行文件。它优先读取可执行文件同目录的 .env，不读取当前工作目录的 .env；没有文件时使用进程环境变量。生产默认插件与核心缓存也定位到可执行文件同目录。

```sh
./deployment/scwc --port=3200 --port-range=20
./deployment/scwc --plugin-dir=/absolute/path/to/plugins
./deployment/scwc --help
```

运行时将内置资源释放到唯一的私有临时目录，插件子进程通过同一可执行文件进入宿主模式；正常退出删除临时资源。运行需要可写的系统临时目录，缓存使用部署目录的 cache/files。强制杀死核心可能遗留临时资源，系统清理临时目录时可回收。

构建后可运行 `bun run test:core-executable` 验证独立部署，需要本机可用 redis-server（或通过 SCWC_TEST_REDIS_SERVER 指定路径）。验证使用临时部署目录、独立 Redis 密码与端口、最小测试插件，不读取部署的真实配置，也不连接现有 Redis；结束后清理测试进程与数据。

核心本身无需预装 Node、Bun 或项目依赖。业务插件仍需提供自己的第三方依赖；特别是原生扩展需匹配打包所用 Node 的 ABI 与目标平台。打包不会替插件安装或编译依赖。

独立核心保留原有命令输入。其 restart 命令与直接启动源码核心一样，仅卸载并结束当前核心；重新拉起需要父进程。使用 ./scwc --terminal 启动多窗口终端，由终端负责重新拉起核心。详见 [终端使用说明](../projects/terminal/README.md)。
