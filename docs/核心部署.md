# 核心服务配置与独立部署

## 源码启动

```sh
bun run dev:server --plugin-dir=./my-plugins --port=3200 --port-range=20
node projects/server/index.ts --mode=dev --plugin-dir=./my-plugins
```

源码模式读取仓库根 `.env`，不受启动工作目录影响。文件中提供的键优先于进程环境变量，文件未提供的键使用进程环境变量。CLI 的 port / port-range 优先于这两者。

## 配置

完整模板在 [core.env.example](core.env.example)。无效端口、查询范围或 Redis 配置会明确报错，不静默使用另一个值。

| 配置              | 默认值                 | 说明                                                                       |
| ----------------- | ---------------------- | -------------------------------------------------------------------------- |
| PORT              | 3200                   | HTTP 起始端口，1–65535                                                     |
| PORT_SEARCH_RANGE | 20（自动限制到 65535） | 最大递增偏移；候选范围含起始端口与末端。显式配置不得越过 65535；0 禁止递增 |
| HOST              | <http://localhost>     | 公布服务 URL 的主机前缀，保持现有监听行为                                  |
| TOKEN             | 随机 UUID              | 字面值 null 关闭验证，留空生成随机值                                       |
| REDIS_ENABLED     | true                   | false/0 完全禁用核心 Redis，仅使用内存和文件缓存                           |
| REDIS_HOST        | 127.0.0.1              | 主机名、IPv4 或 IPv6；不含协议                                             |
| REDIS_PORT        | 6379                   | Redis 端口，1–65535                                                        |
| REDIS_USER        | 空                     | 可选 ACL 用户                                                              |
| REDIS_PASSWORD    | 空                     | 可独立设置密码，支持特殊字符；含 # 的值在 .env 中加引号                    |
| REDIS_TIMEOUT     | 5000                   | 连接超时，毫秒，正整数                                                     |
| REDIS_KEY_PREFIX  | cache-redis            | Redis 命名空间；不能为空或含空白、Redis 通配符                             |
| SCWC_PLUGIN_DIR   | 见下文                 | 核心业务插件目录                                                           |
| SCWC_NODE_PATH    | PATH 查找              | 仅 外置 Node 运行时版：合规 Node 文件路径，相对部署目录解析；显式无效值直接报错 |

端口只在绑定返回 EADDRINUSE 时递增，其他错误立即失败。绑定成功后的日志及 `server info` 显示实际端口；浏览器配置仍需填写这个实际端口，本次不引入自动服务发现。

Redis 使用连接选项传递密码，避免拼接 URL 时破坏密码里的特殊字符。Redis key 形如 `<前缀>::plugin:<插件目录名>:<key>`；核心清理缓存仅影响当前前缀，多个部署共享 Redis 时请使用不同前缀。旧版本可能存在双重前缀的缓存键，升级后不读取这些旧缓存，等待原 TTL 到期即可。

Redis 不是启动前必须就绪的服务，但默认启用时会创建 Redis 存储，离线可能报错或延迟缓存操作。无需 Redis 时在源码根或可执行文件同目录 .env 设置 `REDIS_ENABLED=false`；不创建客户端、不尝试连接，也不校验其余 Redis 参数。内存缓存及文件缓存仍可用，但内存元数据不跨重启保留。插件自行创建的 Redis 客户端不受核心开关控制。

插件目录优先级：命令行 `--plugin-dir`（需要时确认）→ SCWC_PLUGIN_DIR → 模式默认值。开发模式默认仓库的 `projects/server/plugins`；生产模式默认程序所在目录的 `plugins`（源码入口所在目录是 `projects/server`）。环境变量中的相对路径以 `.env` 配置目录为基准，CLI 相对路径以启动工作目录为基准。

同时指定 SCWC_PLUGIN_DIR 和 --plugin-dir 时打印“环境中的 SCWC_PLUGIN_DIR 将会被覆盖”，直接运行核心时输入 y 才覆盖；通过终端启动时在底部输入 :y 加 Enter 确认，:n / Esc / 其他输入取消。确认发生在 HTTP 服务启动和插件加载之前；通过 setup.ts 启动时，同样由核心确认。没有设置环境目录时，CLI 直接生效。

## 构建运行时发行包

两套构建均输出 ZIP，核心产物直接放在 `dist/core/`。压缩包内是部署文件，不增加外层目录；请解压到一个独立部署目录再运行。构建使用系统临时目录，归档完成后原子替换同名 ZIP，失败保留旧压缩包。

| 版本 | 构建 Node 要求 | 部署 Node 要求 | 自动选择本机系统的命令 |
| --- | --- | --- | --- |
| 内置 Node 运行时版 | >=25.5，使用 SEA | 无需另装 Node | `bun run build:core:bundled-node` |
| 外置 Node 运行时版 | >=25 | 匹配平台/架构的 Node >=25、Node-API >=10 | `bun run build:core:external-node` |

| 系统 | 内置 Node 构建 | 外置 Node 构建 |
| --- | --- | --- |
| Windows | `bun run build:core:bundled-node:windows` | `bun run build:core:external-node:windows` |
| Linux | `bun run build:core:bundled-node:linux` | `bun run build:core:external-node:linux` |
| macOS | `bun run build:core:bundled-node:macos` | `bun run build:core:external-node:macos` |

每个命令都必须在目标系统与架构上原生构建；默认使用 `process.platform` 与 `process.arch`。可追加 `--arch=x64/arm64`，但指定其他系统或架构会报错，因为 SQLite、esbuild、Rolldown、Lightning CSS 等资源含原生代码。Linux 区分 glibc/musl，musl 产物带 `-musl` 后缀。macOS 内置 Node 可执行文件自动临时签名。

产物命名：`dist/core/scwc-bundled-node-<windows|linux|macos>-<x64|arm64>[-musl].zip` 与 `dist/core/scwc-external-node-<windows|linux|macos>-<x64|arm64>[-musl].zip`。内置 Node 包的可执行文件采用相同名称，Windows 另加 `.exe`；外置 Node 包使用 `start.cjs`、Windows 的 `start.ps1` 或 Linux/macOS 的 `start.sh`。

### 插件选择与默认环境

两套命令共用以下参数，支持 `--参数=值` 或 `--参数 值`：

| 参数 | 值 | 默认 | 行为 |
| --- | --- | --- | --- |
| `--terminal-plugins` | `true` / `false` | `false` | 附带当前仓库 `projects/terminal/plugins/` 中的终端插件，排除 `template` |
| `--core-plugins` | `none` / `all` / `enabled` | `none` | 不附带 / 附带全部 / 仅附带 `package.json` 中 `enabled !== false` 的核心插件；来源为 `projects/server/plugins/`，排除 `template` 与 `test` 示例 |

```sh
bun run build:core:bundled-node:macos --terminal-plugins=true --core-plugins=enabled
bun run build:core:external-node:macos --terminal-plugins=false --core-plugins=all
```

启用状态与核心加载器保持一致：明确 `enabled=false` 才禁用，省略该键也视为启用。两份 `plugin-env.d.ts` 始终位于 `plugins/` 和 `terminal/plugins/`，即使选择不附带插件也保留。终端内建 `scwc` 命令适配属于编译后的宿主能力，始终可用；附带其源码时不会重复加载。

附带插件包含源码、资源及已安装的私有生产依赖（按插件 `dependencies` 递归收集）。不携带开发依赖、Git/AOCI 状态、真实 `.env` 或插件根目录的 `data/cache/logs`。未安装的必需依赖会使构建报错，不联网安装；插件依赖的 FFmpeg 等系统工具仍需部署机提供。已存在的插件页面随插件资源附带，缺页时核心可按既有规则构建。

`docs/core.env.example` 以 `.env` 文件名进入 ZIP，保留全部注释并填入固定默认值；TOKEN、Redis 用户/密码、Node 路径等没有固定默认值的项留空，不读取当前项目的真实 `.env`。TOKEN 留空会生成随机 UUID；默认 Redis 启用，无需 Redis 时编辑为 `REDIS_ENABLED=false`。内置 `.env` 中提供的键优先于进程环境。配置了默认 `SCWC_PLUGIN_DIR=./plugins` 时，CLI `--plugin-dir` 覆盖仍需要确认。

### 外置 Node 运行时版

解压后包含 `start.cjs`、系统启动器、`build-info.json`、`contents.json`、`package.json`、`README.md`、`LICENSE`、`.env`、两个插件目录及 `runtime/`。runtime 内有七个 CJS 入口、完整共享包树、静态页面/图标/字体和资源清单。工具包可能包含自己的平台可执行文件，包内没有 Node 本体。

```sh
node start.cjs
node start.cjs --no-terminal
node start.cjs --build-plugin-web /absolute/path/to/plugin
# Windows: ./start.ps1；Linux/macOS: ./start.sh 或 sh ./start.sh
```

启动器读取相邻 `.env` 的 `SCWC_NODE_PATH`，未指定时从 PATH 寻找合规 Node；相对路径按解压目录解析，显式无效路径不回退。路径支持单双引号、`export` 和行尾注释，不执行 `.env` 中的内容。直接 `node start.cjs` 也会读取该配置并在需要时转交给指定 Node。

核心、两类插件宿主、SDK Worker 与 Vite 构建进程沿用同一 Node。部署环境检查版本、Node-API、系统、架构与 Linux libc。部署目录可以整体搬移，不读取启动 cwd 的 `.env`；`SCWC_APP_DIR`、`SCWC_RUNTIME_ROOT`、`SCWC_DISTRIBUTION_MODE` 为内部字段，不接受 `.env` 覆盖。开发类型仍引用源码 SDK 声明，两份公共声明不等于完整独立开发套件。

### 内置 Node 运行时版

解压后包含可执行文件、默认 `.env`、`README.md`、`LICENSE` 与两个插件目录。Node、核心依赖、多窗口终端、两类宿主、Web 页面、scwcutils、公共资源及页面构建工具链都包含在 SEA 中。

```sh
# macOS arm64 示例；其他系统/架构使用 ZIP 中实际名称
./scwc-bundled-node-macos-arm64
./scwc-bundled-node-macos-arm64 --no-terminal
./scwc-bundled-node-macos-arm64 --build-plugin-web /absolute/path/to/plugin
```

采用 Node SEA，以保持已有 Node 插件及高级 IPC 序列化兼容。机制参考 [Node 官方单文件应用文档](https://nodejs.org/api/single-executable-applications.html)。

核心、终端和两类宿主在构建时均经 esbuild 转换为 JavaScript、合并依赖、tree shaking 和压缩，保留函数/类名便于异常诊断。这里没有 SSR 页面水合；如果“水合”指依赖合并，bundle 已覆盖。Node 直接运行 TS 会先擦除类型，再执行 JavaScript，不会利用 TS 类型做额外运行优化；预编译主要省去加载时的类型处理，合并和压缩主要减少读取与解析体积，业务运行速度仍取决于实际 JS、I/O 和算法。参见 [Node TypeScript 文档](https://nodejs.org/api/typescript.html) 与 [esbuild 构建选项](https://esbuild.github.io/api/)。

可从其他工作目录启动可执行文件；优先读取可执行文件同目录 `.env`，生产插件与核心缓存也定位到该目录。直接运行 ZIP 内的实际可执行文件名并追加 `--port=3200 --port-range=20`、`--plugin-dir=/absolute/path/to/plugins` 或 `--help`。

运行时将内置资源释放到唯一的私有临时目录，插件子进程通过同一可执行文件进入宿主模式；正常退出删除临时资源。运行需要可写的系统临时目录，缓存使用部署目录的 cache/files。强制杀死核心可能遗留临时资源，系统清理临时目录时可回收。

构建后可运行 `bun run test:core-bundled-node` 验证独立部署，需要本机可用 redis-server（或通过 SCWC_TEST_REDIS_SERVER 指定路径）。验证使用临时部署目录、独立 Redis 密码与端口、最小测试插件，不读取部署的真实配置，也不连接现有 Redis；结束后清理测试进程与数据。

核心本身无需预装 Node、Bun 或项目依赖。业务插件通过 `scwc:deps` 使用核心明确提供的 Axios、Chalk、Zod、SQLite、Trash、File Type、fflate 时，无需在插件目录安装这些包。核心保留 SQLite/Trash 的原始运行资源和传递依赖作为 SEA assets，释放到私有临时目录；纯 JS 共享依赖合并在宿主中。根 package.json 的其他依赖不会自动开放；插件自身依赖仍需提供，原生依赖须匹配构建运行时与目标平台。

共享入口是由宿主钩子提供的虚拟模块，无需发布同名 npm 包。开发类型通过源码中的 `projects/server/plugin/sdk/modules.d.ts` 和 `projects/server/plugins/plugin-env.d.ts` 获取；模板已配置这两份文件。独立目录开发需显式指定它们的路径，核心工作区须已安装类型依赖。当前没有独立类型发行包；可执行文件不包含供 TypeScript 使用的 SDK 声明。Worker 通过 `scwc:runtime` 的 createPluginWorker 注册各自的钩子，详见 [共享 SDK](../projects/server/plugin/sdk/README.md)。

## 插件前端交付与构建

插件开发者可提供完整前端产物，或提供 Vite 源码/配置并保留 package.json 的 `build:web: "vite build --config vite.config.ts"`。ui.entry HTML 存在时直接加载；缺失时核心在 onLoad 前构建，成功才激活。构建不要求单插件动态加载/卸载；未激活插件修复后重启核心。已有产物不因根依赖升级自动重建。

SEA 内置 Vite、vite-plugin-monkey、esbuild、本机原生绑定和浏览器共享白名单（Lit/@lit、Zod、CodeMirror 等）的原始模块，不另装 Node/Vite。构建优先插件私有依赖，缺失的白名单包回退核心，现有 Lit 导入无需改写；scwc:deps 的浏览器 Zod 别名自动注入。额外 Vite 插件/预处理器或私有依赖需插件自行提供，不自动联网安装。

运行中使用 `plugin build-web <插件目录名>`；也可 `<可执行文件> --build-plugin-web <插件目录>` 或源码 `bun run build:plugin-web --directory <插件目录>` 独立构建，不启动 HTTP/Redis。使用原生可擦除的 TS/JS 配置，outDir 必须位于插件内的独立产物目录；核心固定资源 base。普通构建失败保留旧页面，同插件合并请求、全局串行，五分钟截止；重建后刷新页面，不重载后端。完整限制见 [页面构建](../projects/server/plugin/web/README.md)，依赖维护步骤见 [项目地图](map.md)。

直接运行 ZIP 中的可执行文件默认启动多窗口终端，由终端负责命令窗口与核心重启；旧 --terminal 参数仍兼容。需要普通逐行核心时为可执行文件追加 --no-terminal；此模式的 restart 与直接启动源码核心一样，仅卸载并结束当前核心，重新拉起需要父进程。源码启动命令不变。插件宿主、终端插件宿主和 --build-plugin-web 等独立构建分支优先，不会进入默认终端。详见 [终端使用说明](../projects/terminal/README.md)。

三系统自动构建见 [工作流](../.github/workflows/build-core-releases.yml)：分别构建两种 ZIP，再从 ZIP 解压运行集成测试并上传产物。ZIP 保存 Unix 执行权限，解压工具须支持这些属性。Windows/Linux/macOS x64 的本次改动需在对应环境验证。fflate 使用 ZIP32；文件/压缩包上限为 4 GiB、条目上限 65535，超限明确失败并保留旧产物。
