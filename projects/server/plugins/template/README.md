# 模板插件 · 接入验证

本模板保留抓取、命令和用户脚本控件示例，提供 Vite + Lit 验证页、声明式主侧栏/辅助页/状态项及后端配置。当前 manifest 为 `enabled: true`；复制时按需调整。加载时不自动创建通知或任务，不自动运行探针。没有新增依赖；构建使用核心共享的 Lit、Vite 和 `@scwc/vite-plugin`。

完整接口覆盖、测试证据与已知核心缺口见 [接口覆盖表](docs/coverage.md)，源码分工见 [项目地图](docs/map.md)。

## 最短接入与操作

在本目录执行 `bun run check`、`bun run build:web`、`bun run test:integration`。后端只使用 Node 原生可擦除 TS。普通页必须先 `await sdk.ready`；本模板检查 `pageApiVersion=2` 与 `ui.handlers`，旧 SDK 会显示明确的版本错误，不恢复旧接口。

1. 使用已有 `http://localhost:3201/web/`，插件菜单“重启后端”仅重载 template，再刷新普通插件页。不要另起开发服务器。
2. 主侧栏“模板验证”：名称/参数、数据/监听、配置/核心、UI/生命周期四个标签。输入后点“同域异步链”，观察字段规范化；“数据/监听”分别增加前后端计数。嵌套标签支持方向键、Home/End，内容更新保持稳定 key/id。
3. 普通页面“统一模板接入”：先读完整配置基线，再通过本插件 `/validation/config` 业务 API 写入；可从另一页修改制造 CAS 冲突，之后显式选择保留草稿或接受远端值。完整/选定键快照与三种配置订阅记录在折叠结果区；无网络轮询。
4. “页面信息→配置”才是核心配置表单；保存、重置、接受远端值、保留草稿由核心专用处理器执行。插件自定义模板不调用这些专用绑定。
5. 普通页的 `UI ...` 按钮可切换辅助 JSON/HTML、隐藏/恢复页面信息、三种 tooltip 格式、状态项可见/禁用状态，以及各句柄释放。`UI dispose` 在同一事务内先移除所有视图/属性引用，再释放处理器与资源；“恢复声明式演示”重建一次，每区域始终最多一项。
6. “释放前端处理器”先移除后端视图引用，再 `await dispose()` 页面处理器。重新恢复时先注册页面处理器再恢复后端贡献。后端 inspector 的 tab 定向失效与执行中改模板的回执限制见覆盖表，不能按按钮点击宣称成功。

## 产物版本问题

本次发现旧 `web/dist/assets/index-DeR2zT9o.js` 仍调用 `page.register`，而源文件已迁移到 `ui.handlers.register`。实际注入的旧 `scwcutils.iife.mvsaa0dd.js` 还保留旧 page 接口且没有 `ui.handlers`，说明模板和 SDK 都存在构建版本滞后。模板通过 `build:web` 重建；SDK 经用户特别授权，只运行 `projects/webutils` 的 `bun run build` 重建产物，未修改核心/SDK 源码。核心路由动态注入最新 SDK；已有插件 HTML 缓存需插件重载后刷新，不能手改压缩 JS 或补回 page.register。

构建产物按仓库规则忽略，提交源码后在目标环境重新构建。SDK 的时间戳文件名每次构建都会改变，不应在插件中硬编码该文件名。

## 启动

在仓库根目录使用已安装的工作区依赖：

```sh
node projects/server/plugin/web/cli.ts --directory projects/server/plugins/template
./node_modules/.bin/tsc -p projects/server/plugins/template/tsconfig.json
./node_modules/.bin/tsc -p projects/server/plugins/template/web/tsconfig.json
node --test projects/server/plugins/template/tests/integration.test.mjs
```

通过核心插件管理启用 `template`，打开「模板 · 接入验证」。浏览器入口为核心同源的 `/web/page/plugin/template/`。已有核心进程需要重载插件后端，页面源码更新后先构建再刷新。HTML 缺失时核心按 `build:web` 自动构建；已有 HTML 不会自动重建。`web/dist` 为忽略的构建产物，发布预构建页面时必须带齐整个目录。

直接启动 Vite 开发服务器不会注入 `scwcutils`。验证浏览器直接打开的场景，请使用页面上的「在浏览器中直接打开」，仍由核心提供页面和授权。模板复制到其他目录后，Vite 配置按实际目录名生成资源前缀。

集成测试监听回环临时端口，沙箱需允许本机监听。测试临时数据仅写在 `template/tests/.tmp-*`，正常结束自动清理；测试专用 Node hook 阻止真实 `.env` 覆盖路径，不读取用户数据库或启用其他插件。Node 子进程使用原生类型擦除，前端执行当前 SDK 源码和真实 Vite 产物。

## 本次需要插件配合的验证点

| 功能           | 模板接入位置                                       | 判定证据                                                                  |
| -------------- | -------------------------------------------------- | ------------------------------------------------------------------------- |
| 外部页面状态   | `externalState.get/onChange`                       | 工作台、直接打开、聚焦、可见状态及事件                                    |
| 未标记请求保护 | 不传 `interruptible` 的 Fetch、Resource、WebSocket | 执行期间不暂停页面、不空闲断连；所有保护释放后才重新计时                  |
| 可中断请求     | 显式 `{ interruptible: true }` 的三种通道          | 空闲断连后暂停；恢复后 Fetch 新 attempt、资源 src 恢复、Socket 新连接编号 |
| 页面活动       | `lifecycle.register`、本地心跳                     | 隐藏时受未标记请求保护，完成后才收到 onSuspend；恢复后计数继续            |
| 前端任务与通知 | `scwcutils.tasks/logger`                           | 控制对象返回的状态、核心任务列表和通知 UI                                 |
| 后端任务与通知 | `onLoad` 保存 `context.workbench`                  | API → 插件子进程 → 核心持久服务；按钮函数在后端执行                       |
| 内置任务       | `tasks.start(当前插件, 'build-ui')`                | 真实页面构建任务及核心日志                                                |

任务按钮位置、空闲/运行/完成未读图标、弹窗标题「任务」、不自动弹窗、通知中心可见区域及加载条尺寸，需要在核心 UI 验收。模板负责产生真实数据，不自行绘制替代通知或任务窗口。核心终端执行请求的分类也属于核心回归范围，不能用模板 GET 探针代替终端执行。

## 最小手工验收

建议先完成任务/通知验证并结束所有运行中的任务，再测空闲断连。其他页面任务、命令执行或默认 WebSocket 会共同保护核心连接。

1. **外部状态**：工作台中应 `inWorkbench=true`、`inBrowser=false`；切换标签和焦点应改变 `visible/focused`。通过页面链接直接打开应为 `false/true`，`focused/visible` 显示「无值」。独立页面不参与工作台空闲断连与隐藏暂停流程。
2. **未标记请求与隐藏保护**：启用核心节能功能，先发起默认保护 Fetch（建议 90 秒），切换到其他标签。隐藏超过 30 秒仍不应暂停；请求结束后才可收到暂停。Resource 用相同步骤；默认 WebSocket 在整个连接生命周期保护活动，需主动关闭才释放。
3. **全部完成后重计时**：核心空闲阈值设为 1 分钟。发起默认保护 Fetch A（90 秒），20 秒后发起 B（90 秒）；A 完成时不应开始断连，B 完成后应重新等待完整 1 分钟。倒计时开始 30 秒后再发起默认保护 Fetch C（90 秒），应停止原倒计时，等 C 完成后重新等待完整阈值。不要在等待期间点击查询按钮或操作其他工作区。
4. **可中断 Fetch**：关闭所有保护请求、结束前后端任务，将延时设为 180 秒，发起可中断 Fetch 后等待核心空闲断连。打开浏览器网络面板保留日志，确认原请求被中止；恢复交互后新请求返回，同一个 `run` 应出现两个 `started` 与不同 attempt。页面的「读取后端请求证据」按需查询；它自身会恢复活动。
5. **可中断资源**：发起可中断 Resource，确保图片仍未返回时核心断连；DOM `src` 应移除，恢复后还原同一 URL 并重新加载。资源返回 `Cache-Control: no-store`。单纯调用 `resource()` 生成 URL 不发请求；必须绑定 DOM。本例使用 Light DOM，因为当前 SDK 的资源观察器不进入 Shadow DOM。
6. **可中断 Socket**：连接后记录连接编号，空闲断连后核心应关闭底层连接；恢复后保持同一代理和回调，收到新编号。点击 echo 检查发送。手动关闭后再次断连/恢复不应重建。可中断 Fetch 点击「取消全部」后也不应重发。网络面板离线不等于核心主动暂停，不能作为上述步骤的替代。
7. **任务（分别选前端、后端）**：创建 → 开始 → 进度 50% → 更新内容 → 成功；窗口不应自动出现。确认运行图标、完成未读图标，点击底部通知按钮左侧的任务按钮后才显示「任务」，已完成项变为已读。另建任务分别测试失败与取消。页面创建的运行任务会申请活动保护，关闭页面后应由 SDK 释放；后端任务不依附页面存活。
8. **通知（分别选前端、后端）**：创建时为不定进度、`autoRead=false`，分别在浮层和通知中心检查底部等宽 4px 加载条。切到 50%、隐藏、再切回不定进度；更新内容和级别。通知中心打开并滚动通知进入/离开视口，再「查询控制对象」核对 `visible`，注意可见心跳有最长 20 秒过期窗口，可见并不代表已读。手动标已读/恢复未读均应生效。替换 4 个按钮后点击其按钮，刷新查询结果核对回调；最后主动关闭，通知中心和浮层均应移除。
9. **内置任务**：点击「运行内置页面构建任务」，观察核心 `build-ui` 的真实状态与日志。此按钮使用前端 `tasks.start`；自定义任务的手动更新不能用于驱动内置任务。SDK 还接受 enable/disable/once-disable/reload 等类型；它们会改变插件生命周期，不在本模板的默认最小验证中自动执行，`rescan` 仅核心可调用。

## 结果解释与限制

- 页面记录操作和返回结果，快照是最近一次查询，不自动轮询网络，避免干扰空闲计时。点击通知按钮回调后可手动刷新快照。
- 后端只延时只读响应，浏览器 abort 不代表后端执行被取消；观察同一 `run` 的 attempt 判断重发，不能将后端 `finished` 当作浏览器收到响应。
- `progress=null` 为不定进度，`0–100` 为百分比，`false` 隐藏。通知 `isVisible()` 指通知中心视口，浮层显示不改变此值；已读由 `markRead` 独立控制。
- 自动测试覆盖真实 IPC/HTTP/SQLite、前后端通知回调、任务更新、SDK MessagePort 状态与暂停、Fetch 重放/主动取消、资源 DOM 解绑还原、真实 Socket 保护与重连，以及 Lit 按钮更新。JSDOM 不做像素布局和真实图片解码，宿主消息夹具不代表完整工作台的空闲调度；第 2–9 步中的核心 UI 和计时仍需手工验收。
- 本次不维护 AOCI；待其他分支维护完成并获准后再统一对齐。
